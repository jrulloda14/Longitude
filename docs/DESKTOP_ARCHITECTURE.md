# Shared desktop architecture — Milestones 5A/5B

The Tauri 2 application embeds the existing Vite/React frontend. `main` and `widget` use WebView2 on Windows and system WKWebView on macOS, running the same entry/component tree. The platform adapter derives its label/OS from native APIs; it does not select macOS chrome from a saved Windows preview preference. No second frontend or timezone/scheduling implementation exists. Actual Mac compilation/runtime acceptance remains pending; the code/configuration below describes intended host behavior, not a Mac test result.

## macOS host integration

The Mac override supplies a decorated overlay title bar with native traffic lights. The existing React title bar reserves an 80-point inset rather than drawing duplicate controls; the browser design preview remains unchanged. Native application menus provide standard editing, Services, Hide, Window and close/fullscreen actions. Application-owned IDs use a `mac:` prefix and dispatch through the same canonical actions as the tray without double dispatch. Groups refresh both menus. The menu-bar icon is a monochrome 36px template derived from the original meridian mark; macOS supplies appearance/highlight colors. Primary status-item click opens its menu rather than copying Windows left-click toggle behavior.

Mac is a regular Dock application (`LSUIElement=false`). Close=Hide may hide the main window even without a status item because Dock reopen is available; Windows still requires a tray entry point or quits. Reopen/second launch unhides and focuses main; hiding all windows does not force them back on Mac. Native Quit/Cmd+Q/OS exit requests use the same client flush barrier. Hidden webviews stay alive; explicit Quit cleans up shortcuts. Fullscreen geometry is neither clamped nor saved as ordinary placement. The widget uses public Tauri pin/Spaces APIs; actual Spaces/fullscreen/Stage Manager behavior remains a hardware acceptance item, not a promise of visibility over protected/fullscreen surfaces.

Fresh Mac profiles seed `Alt+Super+T` (Option+Command+T); existing/imported shortcuts are preserved. The existing schema/recovery, fixed-key storage, CAS, locks and application-directory resolver are unchanged. The autostart plugin defaults to LaunchAgent; no AppleScript automation is requested. Theme follows existing `prefers-color-scheme` handling and explicit overrides; sizes use logical coordinates and stored physical/scale pairs. Retina, appearance and filesystem behavior must still be verified on the actual host.

Transparent Mac widget compositing requires Tauri's Mac-only private-API feature. It adds no crate or IPC permission but excludes App Store distribution. Hardened-runtime configuration and narrow permissions remain; signing/notarization is documented separately in [build instructions](BUILD_AND_RELEASE.md). [Mac acceptance](MACOS_ACCEPTANCE.md) distinguishes native verification from policy/configuration tests.

## State and persistence

`DesktopStateClient` uses the existing TypeScript reducer, queues actions and renders optimistic changes immediately. Stable group/location IDs are allocated before queuing creation/duplication actions. A batch proposes a validated complete state against an authority revision. Rust validates structure/bounds and serializes conditional transactions. Accepted revisions are broadcast to both windows; conflicts rebase queued actions against the canonical snapshot. Origin/request IDs acknowledge a batch exactly once; stale broadcasts are ignored. Conflict retries are bounded. Errors retain pending edits and offer Retry or Discard. This bridge never broadcasts received snapshots back as actions.

Only the main window can hydrate/migrate the fixed configuration through the Milestone 4 schema/repository. Windows are created after native services are registered, preventing initial IPC races. Once initialized, raw frontend commits are rejected: the Rust authority owns durable writes. A refreshed/reopened WebView receives the latest authority snapshot rather than rereading old session state from disk. Mode/visibility are per-window; shared selected instants, groups, reference zones, settings and meeting inputs remain canonical. Live ticks and temporary recommendation state are not persisted. Full process restart restores durable settings and returns to live Clock view.

Rust does not interpret timezone rules. The established TypeScript schema normalizes/validates timezone identifiers before IPC; native validation additionally guards sizes, field types, IDs/references, intervals and preference ranges. No Rust tzdb dependency or secondary timezone calculator is introduced. [PERSISTENCE.md](PERSISTENCE.md) remains the shared schema contract.

Native files use Tauri `app_config_dir`, with fixed filenames `configuration.json`, `legacy-v1.json` and lock files. A standard-library file lock protects a raw-byte compare-and-swap; contention fails visibly rather than blocking indefinitely. The authority retains expected disk bytes and refuses external edits instead of silently merging/overwriting them. A same-directory tempfile is written and synced before atomic replacement; the repository's current/previous/recovery strings travel together. Legacy data is read-only. Recovery/schema limits and unknown future versions remain protected. This tests interruption/restart behavior, not a physical power-loss guarantee. Windows filesystem rename metadata durability remains subject to the OS/filesystem.

Window geometry is a separate best-effort placement cache under the fixed `window-layout` directory, outside the canonical versioned user configuration. Invalid cache data resets placement to visible defaults rather than the user configuration's recovery history. Save content dimensions plus scale and physical position; restore logical dimensions during window creation, then clamp position/outer bounds to an actual monitor work area. This avoids treating outer frame dimensions as content dimensions. Preserve prior ordinary bounds when quitting maximized. Removed/negative-coordinate displays and fractional minimum-size calculations have portable tests; physical mixed-DPI behavior requires its own verification.

## Services and lifecycle

Tauri window/tray APIs and official shortcut/autostart plugins implement portable services. Rust modules for authority, atomic storage and placement have no Windows path or registry assumptions. Platform configuration overrides contain the necessary Windows `npm.cmd` launch and NSIS packaging settings. No macOS-specific functionality or override is implemented before 5B approval.

Opening the widget keeps the main window independent. Expand opens the main window and hides the widget; Close widget hides only that window. Main close follows Hide/Quit preferences; hiding requires a tray icon, otherwise close requests Quit. If disabling the tray could leave no visible window, the main window is restored. Tray actions open the main window, toggle the widget, return to Now, open Settings, switch groups and Quit. A second executable launch restores the existing main window through the single-instance plugin.

Widget connection/show reapplies pinning from canonical state, independently of window construction order. This fixes the tested unpinned-restart case. Native preference side effects are rejected before execution in read-only future-schema sessions. Both Quit close preference and tray-disabled close are verified to exit rather than leave an inaccessible process.

Shortcut changes register the replacement before releasing the owned previous shortcut; errors retain/restore prior preferences. Sign-in is opt-in through the existing row. Preference side effects roll back when a durable commit fails. Native errors are surfaced in the existing notification area. Only explicitly implemented capabilities are exposed to JavaScript.

Quit requests a generation-tagged flush from both clients before releasing shortcuts and exiting. Failed or unresponsive clients pause Quit with a visible error; late acknowledgements from an older request cannot satisfy a newer request. Native geometry is saved on hide/normal Quit. OS kill/crash cannot flush uncommitted frontend actions; the storage replacement protects already committed records.

Hidden native windows pause wall-clock ticks and refresh on visibility. Widget preview timeouts only reset their own unchanged selection and are cleared when hidden, so a newer main-window planning selection survives. Existing dial pointer capture and direct-entry behavior are reused.

## Security boundary

Production assets/fonts/workers are local. CSP permits local assets and native IPC, with no remote script/connect origin. Main/widget capabilities allow state/window commands and event listening; only main receives hydration commands. No generic filesystem, shell, HTTP, global-shortcut or autostart JavaScript plugin permissions are granted. Those OS services are owned by Rust. No server, account, synchronization, telemetry or notification plugin is added.

The native dependency review and full resolved notices are in [DESKTOP_DEPENDENCIES.md](DESKTOP_DEPENDENCIES.md) and `NATIVE_THIRD_PARTY_NOTICES.txt`. Debug-only test roots isolate automated configuration/WebView profiles; release builds ignore that environment override. Remote debugging is enabled only by the test launch environment, never by shipped configuration.

See [MILESTONE_5A.md](MILESTONE_5A.md) for exact results and unverified manual checks. Stop for Windows review before 5B.
